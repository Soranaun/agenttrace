# AgentTrace 约三分钟中文演示讲稿

> 目标时长约 3 分钟，含页面点击时间。正式录制前应按本人语速彩排。正文可直接朗读；“操作”不朗读。不要将模拟统计解释为真实业务效果。

## 录制前准备

先启动应用，确认总览只有三条内置记录、运行成功率为 67%，浏览器缩放 100%。依赖提前安装；停止旧服务并重新启动可清空旧会话。录制工作台窗口即可，避免录入其他项目、个人信息或密钥。推荐 1366×768 或更宽画面。

讲稿主线包含文件导入导出。现场模拟作为备用展示，不与完整主线同时展开，以免超时。无需额外准备模型账号。

## 0:00—0:25｜背景与定位

**操作：** 停留在“运行总览”。

各位评委好，我的作品是 AgentTrace，一个轻量级的 Agent 执行追踪、离线回放和差异诊断工具。它关注一个具体问题：任务失败后，怎样看清哪一步出了错，以及修改前后究竟发生了什么。当前版本使用 Python 和 Streamlit，在本地运行，不需要模型密钥或数据库服务。

## 0:25—0:55｜正常与失败的执行证据

**操作：** 选择“模拟 · 正常运行”，展示时间线；再选择“模拟 · 工具调用失败”，滚动到红色异常详情。

这里有正常、工具失败和修复成功三组模拟记录。每一步都保存了输入、输出、状态和耗时。失败样例中，查询工具收到小写编码 a-101，而本地字典要求大写编码，因此抛出了 KeyError。我们能直接看到失败步骤和原始参数，而不只看到一个最终失败结果。

## 0:55—1:20｜离线回放

**操作：** 打开“离线回放”，选择内置失败记录，点击“下一步”。

现在进行历史回放。这里读取的是已保存记录，不会重新调用模型或工具。我们可以按顺序查看当时的输入、输出和异常。这能帮助课程展示或故障讨论使用同一份证据，也避免再次执行工具产生额外影响。

## 1:20—2:00｜修改前后差异

**操作：** 打开“差异诊断”，保持默认失败到修复成功；展示指标，展开“变化 · 查询库存”。

修复样例新增了编码规范化步骤，把 a-101 转成 A-101，查询就成功了。系统按稳定步骤 ID 对齐两次执行，展示新增步骤、参数变化和错误消失。这里的步骤成功率从百分之五十变为百分之百。累计耗时从六百三十到六百一十二毫秒，但这是固定模拟值，不能作为性能提升结论。系统给出的是记录差异，不是大模型根因分析，也不会自动修复程序。

## 2:00—2:35｜文件交付与复查

**操作：** 返回总览，选择失败记录，点击“下载此运行 JSON”；在侧栏上传该文件。切换回放，选择带 `[导入]` 前缀的记录，点击“下一步”。

运行记录可以下载为 JSON，再从本地导入。现在看到的是刚导入的同一份历史记录，仍然可以逐步回放。这使调试结果能够以文件留存和交流，而不依赖当时的模型服务或运行会话。

## 2:35—3:00｜实现、验证与边界

**操作：** 回到诊断页，指向“下载诊断报告”；不要再展开新的长流程。

当前版本还可以导出诊断报告。项目包含 MIT 许可证、接入说明和三十项已通过测试，也完成了三种屏幕宽度的浏览器验收。它目前面向单用户、顺序执行的本地任务。后续希望先稳定记录格式，再尝试真实任务接入。以上演示是本地模拟，不代表已有真实业务部署。谢谢。

## 超时与备用操作

- 如果文件选择超过预期：停在“下载此运行 JSON”，说明可重新导入，直接进入结尾。完整导入证据已留在验收材料中，不要把未完成点击说成已经完成。
- 如评委希望看即时执行：关闭侧栏“启用编码规范化修复”，执行一次本地模拟；开启后再执行一次，在诊断页选择两条 `[现场]` 记录。此流程约需额外 30—60 秒，耗时为实际测量且可能非常短。
- 若被问“创新是什么”：回答为本地记录、历史回放与差异证据的轻量化整合；不主张新模型算法、行业首创或尚未证实的效率收益。
