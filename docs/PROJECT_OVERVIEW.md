# AgentTrace 中文作品介绍

> 项目定位：轻量级开源 AI Agent 执行追踪、离线故障回放与差异诊断工具。本文对应当前工作区 MVP；截至 2026-10-23，本文列出的六项 MVP 功能已实现，后续规划单独列示。所有内置和现场演示数据均标记为模拟数据。

## 一、项目背景

一个 Agent 任务通常包含任务理解、参数处理、工具调用、结果组织等步骤。仅查看最终回答，难以判断异常发生在哪一步，也难以解释修改前后的执行差异。教学、课程项目和早期原型开发需要能够直接运行、方便检查和分享的调试材料。

AgentTrace 将一次执行保存为结构化记录，用中文工作台呈现过程，再通过历史回放和运行对比帮助开发者检查故障。项目当前围绕本地顺序执行的任务构建，不依赖在线模型服务。

## 二、要解决的痛点

| 痛点 | 当前解决方式 | 范围 |
| --- | --- | --- |
| 最终结果不能展示中间过程 | 按步骤记录输入、输出、工具、状态、耗时与异常 | 需要开发者使用记录器接入，不能自动采集任意 Agent |
| 重新运行可能无法重现原来的输入输出 | JSON 保存历史证据，按执行顺序离线查看 | 回放已有记录，不恢复运行时环境，也不重新执行模型或工具 |
| 修改后难以解释变化 | 使用稳定步骤 ID 匹配两次记录，展示新增、缺失、变化及错误恢复 | 不自动推断根因，不保证两次任务语义相同 |
| 展示依赖账号、网络或复杂部署 | Python + Streamlit 本地工作台，内置模拟样例 | 首次安装依赖仍需包源；当前不是打包好的独立可执行程序 |

## 三、解决方案与使用闭环

开发者通过 `TraceRecorder.step(...)` 包裹执行步骤，在步骤内填写输出；记录器测量耗时，记录异常并重新抛出。完整运行可以保存为 JSON。工作台加载项目内的记录或用户上传文件，支持检查详情、逐步回放、选择两次运行对比以及下载记录和诊断报告。

工作流为：**执行并记录 → 本地 JSON 留存 → 历史查看与回放 → 比较修改前后 → 导出证据**。其中“修复”由演示代码或开发者实施，AgentTrace 负责记录和展示，不会自动修改被追踪程序。

## 四、核心功能

1. **执行追踪**：Run / Step 数据结构记录运行和步骤；步骤包含稳定 ID、名称、类型、工具、输入输出、状态、开始时间、耗时和错误信息。
2. **中文可视化**：运行列表、运行成功率、步骤成功率、累计步骤耗时、顺序时间线、失败高亮、输入输出详情。
3. **离线故障回放**：读取本地 JSON，通过上一步、下一步和步骤选择器查看历史证据；页面明确标注不会重新调用模型或工具。
4. **执行差异诊断**：按稳定步骤 ID 匹配，比较内容、状态、工具、错误和步骤位置，单独展示耗时；输出可读总结。原失败步骤被删除时，会提示“不能视为修复”。
5. **文件交换**：支持运行 JSON 导入导出与诊断报告下载；单文件上限 5 MB，无效记录显示校验错误，相同内容重复导入不会重复增加导入条目。
6. **现场模拟**：在侧栏切换编码规范化修复，真实执行一个本地字典查询工具，生成新的模拟运行记录；不调用模型、外部库存系统或付费 API。

## 五、技术实现

| 模块 | 实现及证据 |
| --- | --- |
| 数据模型 | [`models.py`](../agenttrace/models.py)：Python dataclass、JSON schema 版本号、状态与耗时校验；拒绝非有限数值与累计耗时溢出 |
| 追踪记录 | [`recorder.py`](../agenttrace/recorder.py)：上下文管理器、UTC 时间、`perf_counter` 计时；记录后继续抛出业务异常 |
| 数据加载 | [`storage.py`](../agenttrace/storage.py)：读取本地 JSON、大小限制、坏文件隔离；不使用数据库服务器 |
| 差异分析 | [`diagnostics.py`](../agenttrace/diagnostics.py)：确定性字段比较和诊断总结，不依赖大模型 |
| 展示界面 | [`app.py`](../app.py)：Streamlit、pandas 和 Vega-Lite 时间线；紧凑表格与可展开详情 |
| 样例与工具 | [`demo.py`](../agenttrace/demo.py) 和 [`data/runs/`](../data/runs/)：库存查询模拟、三组历史记录 |
| 工程验证 | [`tests/`](../tests/)：30 项 pytest 测试；[`browser_acceptance.py`](../scripts/browser_acceptance.py)：可选真实 Chrome 验收 |

已在 Windows / Python 3.12.1 验证。依赖版本、安装命令和启动方式见 [README](../README.md)。应用运行不需要 Docker、模型密钥或数据库服务。

## 六、创新点与工程价值

本作品的创新定位是面向课程和原型开发的工程整合与交互设计，**不主张提出新的模型算法或行业首创能力**。

- **将历史回放与重新执行明确区分**：离线查看已有输入输出，避免演示或排查时意外重复触发工具；测试验证回放不会执行工具。
- **以稳定步骤 ID 连接“失败—修改—恢复”的证据链**：同一步骤即使内容或位置变化仍可对照；对被删除的失败步骤不会直接宣称修复成功。
- **无需模型的可复核演示闭环**：本地模拟工具产生可解析记录，导出后可重新导入查看。固定样例方便重复演示，现场模拟提供实际执行路径。
- **降低上手和解释成本**：中文界面、本地 JSON、Windows 启动脚本，以及同时展示摘要和完整步骤详情，使过程和变化便于说明。

上述价值由代码和样例支持；当前没有对其他工具的系统性评测，也没有量化调试时间、性能收益或用户规模的证据。

## 七、应用场景与当前验证

**已验证场景：校园商品库存查询模拟。** 输入 `a-101` 时，本地工具抛出 `KeyError`；开启修复后，新增规范化步骤将编码变为 `A-101`，查询成功。三组历史样例分别为正常、失败和修复后成功。

| 样例 | 步骤成功率 | 累计步骤耗时 |
| --- | --- | --- |
| 正常运行 | 100% | 620 ms |
| 工具调用失败 | 50% | 630 ms |
| 修复后成功 | 100% | 612 ms |

这些耗时为演示设定，不能证明性能优化。步骤成功率是记录中的步骤状态统计，不是模型准确率或真实业务成功率。现场模拟使用实际计时，因此数值通常更小且会波动。

**可尝试的应用方向（尚无真实用户部署证据）**：Agent 教学过程展示、课程项目故障报告、个人工具调用脚本调试、团队用脱敏 JSON 交流问题。接入时仍需自行添加记录代码和保护敏感数据。

## 八、开源治理与可持续维护

仓库包含 [MIT LICENSE](../LICENSE)、运行说明、样例、测试和验收记录。[贡献指南](../CONTRIBUTING.md)，约定问题报告、修改范围、回归测试和数据脱敏要求。现有许可证的署名保持原样，提交者需自行核对署名和参赛权属信息。

这些文件建立了基础协作规则。目前未配置自动化 CI，也没有社区规模或稳定维护团队的证据。源码版本以公开仓库的提交 SHA 标识，问题与贡献按贡献指南处理。

## 九、局限性与后续规划

当前只支持单用户、本地顺序执行的追踪。耗时为步骤累加，不包含等待间隔，不等于并发任务的墙钟耗时。输入输出需可 JSON 序列化；循环和重试应自行分配独立步骤 ID。上传和现场记录保存在会话中，持久留存需要下载 JSON。

目前没有在线模型适配、自动根因分析、自动修复、并发追踪、权限管理、数据库、自动脱敏或真实业务试点。项目不适合直接作为公网多用户服务。

提交后拟按“格式与回归稳定 → 真实任务小规模接入 → 根据反馈决定扩展”的顺序推进，具体任务和验收条件见 [ROADMAP](ROADMAP.md)。该规划不属于当前已实现功能，不承诺尚未确定的发布时间。
